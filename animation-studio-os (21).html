Page Border

            

              Frame artwork around each page. Design it as a square with the decoration concentrated near the edges and the center transparent or matching your background color — it gets stretched to fill the exact page, so a design that's already frame-shaped (not stretched-looking) avoids distortion.
              Recommended: square, at least 2000×2000px (matches your chosen page size above at print resolution).
            

            
            

          


          

            
Page Break Image

            

              Inserted as its own divider page between sections. Recommended: landscape or square, at least 1200px on the long edge — it's shown at up to 60% of the page size, centered, so it won't be stretched beyond that.
            

            
            

          


          

            
Logo

            

              Shown on the cover page. Recommended: transparent PNG, roughly square, at least 400×400px — it's scaled down to fit, never up, so anything smaller may look soft.
            

            
            

          


          

            
Watermark

            

              Faint mark repeated behind the content on every page. Recommended: simple, high-contrast shape (a monogram or icon works better than fine detail), square, at least 800×800px — fine detail disappears at low opacity.
            

            
            

              
              
            

            

          


          

            
Page Texture

            

              Subtle background texture (paper grain, canvas, etc.) behind everything. Recommended: seamless/tileable, at least 1000×1000px — it's stretched to fill the page, so busy or non-seamless textures may show visible seams.

How this works

          

            Push writes the local Tasks/Shots/Assets/Time Logs/Journal/Team/Reviews to their matching tabs in this project's spreadsheet copy (overwriting those tabs). Pull reads those tabs back and merges rows into the app by ID, adding an ID to any row that doesn't have one yet.
            Run Push after a local working session; run Pull after editing directly in Sheets. There's no live two-way listener — it's a deliberate manual sync so nothing overwrites unexpectedly.
            If an Apps Script Web App URL is set in Settings, that's used automatically (free, no billing). Otherwise it falls back to the Cloud OAuth connection.
          

          

            One device is the Source, every other device Links to it. Only click "Set as Source" once per project — that's what actually creates the spreadsheet. Every other device should use "Link to Source" with that same ID instead, or you'll end up with two separate spreadsheets that never talk to each other.
          

        

      


      
      

        
Settings
Sync configuration. Apps Script is the free, recommended path — no Google Cloud project, no card.


        

          
Install on PC + Android & Sync Between Them

          

            This is one app, not two — the same file becomes an installed app on both PC and Android once it's hosted somewhere with a real web address. Local storage on each device is just a fast cache; the Google Sheet set up under Google Sync is what actually keeps them in sync.
          

          
    
            
  1. Host it. Push this file to a GitHub repo (e.g. your existing account), then in the repo go to Settings → Pages, set the source branch, and save. GitHub gives you a URL like https://yourname.github.io/reponame/animation-studio-os.html. (Any static host works the same way — Netlify Drop, Cloudflare Pages, etc.)
    2. 
            
  2. Install on PC. Open that URL in Chrome or Edge. Click the install icon (⊕ or a small monitor icon) at the right of the address bar → "Install." It now opens in its own window with its own icon, no browser tabs.
    3. 
            
  3. Install on Android. Open the same URL in Chrome on your phone. Tap the ⋮ menu → "Add to Home screen" / "Install app." It behaves like a native app icon.
    4. 
            
  4. Turn on sync. Set up Google Sync below (Apps Script method, free) from one device first, then open Settings on the other device and enter the same Web App URL, secret, and template spreadsheet ID. Both installs now read and write the same spreadsheet — push after working on one device, pull before starting on the other.
    5. 
          

          

            Local storage on each device still holds a full working copy for offline use — the app works fine on a plane, it just won't reflect the other device's changes until you're back online and push/pull.

Method 1 — Apps Script (free, recommended)

          

            No billing, no Cloud Console project. You paste one script into your spreadsheet and deploy it as a web app — Google hosts it for free on your account.
          

          

          

          

          

          

            
            
          


          
Setup steps

          
    
            
  1. Open your master template spreadsheet.
    2. 
            
  2. Go to Extensions → Apps Script.
    3. 
            
  3. Delete the placeholder code and paste in the script below.
    4. 
            
  4. Change the SECRET value at the top to any private string only you know, and paste that same string into "Shared Secret" above.
    5. 
            
  5. Click Deploy → New deployment. Type: Web app. Execute as: Me. Who has access: Anyone.
    6. 
            
  6. Click Deploy, then Authorize access and approve the permissions prompt (this is just you granting your own script access to your own Drive — no verification, no billing).
    7. 
            
  7. Copy the Web app URL it gives you into "Apps Script Web App URL" above, then click Save Settings.
    8. 
            
  8. Copy your master template spreadsheet's ID from its URL (between /d/ and /edit) into "Master Template Spreadsheet ID" above.
    9. 
            
  9. Go to Google Sync → Test Apps Script Connection.
    10. 
          

          

            Note: "Anyone" access means anyone with the exact URL could call your script — the shared secret is what protects it, so keep it private and don't publish the URL.
          

          

            Already set this up before? The script gained an image-sync feature (used by "☁ Sync to Drive" on assets and board images) — open your existing Apps Script project, replace the code with the version below, then Deploy → Manage deployments → ✎ Edit → New version → Deploy. That keeps your existing Web App URL working, no need to update Settings again.
          

          
          
          
        


        

          
Method 2 — Google Cloud OAuth (advanced)

          

            Only needed if you'd rather sign in with a Google account picker instead of a fixed script URL. Sheets/Drive API usage itself is free — Cloud Console may still nudge you toward its optional free-trial billing signup, which you can skip.
          

          

          

          
          
    
            
  1. Go to console.cloud.google.com and create a new project.
    2. 
            
  2. Open APIs & Services → Library, enable Google Sheets API and Google Drive API (no billing needed for these).
    3. 
            
  3. Open APIs & Services → OAuth consent screen. Choose External, fill in the required fields, add yourself under Test users.
    4. 
            
  4. Open APIs & Services → Credentials → Create Credentials → OAuth client ID. Type: Web application. Under Authorized JavaScript origins, add the exact URL you'll open this file from.
    5. 
            
  5. Copy the Client ID into the field above.
    6. 
            
  6. Still in Credentials, click Create Credentials → API key. Copy it above.
    7. 
            
  7. Click Save Settings, then go to Google Sync → Connect via Cloud OAuth.
    8.
